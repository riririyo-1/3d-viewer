# Docker Compose 環境変数管理

## 方針

役割を明確に、各サービスごとに環境変数を管理する。

| サービス | 環境変数の管理方法 | 役割 |
|----------|--------------------| -----|
| server | server/.env | サーバーだけで利用するもの |
| pipeline | pipeline/.env | パイプラインだけで利用するもの |
| frontend | frontend/.env | フロントエンドだけで利用するもの |
| root | {root}/.env | compose.yaml で利用するもの |

- `{root}/.env`の変数は、`compose.yaml`自体の`${}`参照に利用される。
- `compose.yaml`で読み込んだ`xxx/.env`の変数は、ビルド・立ち上げ後にコンテナ内で参照される。

## 構成

### {root}/.env

| 変数名 | 用途 | 値の例 |
|--------|------|--------|
| POSTGRES_USER | DB healthcheck, DATABASE_URL 構築 | user |
| POSTGRES_PASSWORD | DATABASE_URL 構築 | password |
| POSTGRES_DB | DATABASE_URL 構築 | studio_view |
| MINIO_ROOT_USER | MinIO コンテナの管理者認証 | minioadmin |
| MINIO_ROOT_PASSWORD | MinIO コンテナの管理者認証 | minioadmin |

## 推奨構成

```
project/
├── .env                 # compose.yaml 構築用
├── .env.example
├── compose.yaml
├── server/
│   ├── .env             # server 固有の設定
│   └── .env.example
├── pipeline/
│   ├── .env             # pipeline 固有の設定
│   └── .env.example
└── frontend/
    ├── .env             # frontend 固有の設定
    └── .env.example
```
